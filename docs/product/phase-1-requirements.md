# 时光商城一期需求规格

## 1. 阶段目标

一期目标是交付一个可运行、可演示、可重复验收的多商户商城正向交易闭环。完成后，平台可以创建店铺和基础商品资料，商家可以发布商品、维护库存并发货，买家可以跨店下单、使用虚拟钱包支付并确认收货。

一期不追求完整运营后台，优先级按“交易正确性 > 权限隔离 > 页面完整性 > 运营便利性”排序。

## 2. 一期范围

### 2.1 买家端

| 模块 | 功能点 | 关键规则 | 验收结果 |
| --- | --- | --- | --- |
| 注册登录 | 用户名注册、密码登录、退出、获取当前会话 | 注册同时创建钱包并分配 `CUSTOMER`；停用/锁定/删除账号不可登录 | 可完成从注册到登录，刷新后可恢复会话 |
| 个人资料 | 查看并修改昵称、手机号、邮箱、头像 URL | 用户名不可修改；手机号和邮箱非空时全局唯一 | 修改后 `auth/me` 和页面同步 |
| 地址 | 地址列表、新增、编辑、删除、设默认 | 每用户最多一个未删除默认地址；删除默认地址后不自动选择其他地址 | 结算时只能选择本人有效地址 |
| 商品浏览 | 类目树、品牌、商品列表、商品详情、SKU 选择 | 只展示可购买商品；详情显示实时价格和库存 | 匿名用户可浏览，失效 SKU 不可加购 |
| 购物车 | 加购、改数量、删除、单选、全选、按店铺分组 | 不锁库存、不保存价格；重复加购累加但最多 999 | 页面能标记下架、无库存等失效状态并展示实时价格 |
| 结算 | 选中项预览、地址选择、各店备注、金额确认 | 后端重新定价和验库存；一期运费固定 `0.00` | 预览返回按店铺分组和失效原因 |
| 下单 | 跨店一次提交 | 一个父交易、每店一个子订单；原子锁库存；默认 30 分钟支付 | 重复点击不重复建单，任一 SKU 失败则整体失败 |
| 钱包 | 余额、模拟充值、钱包流水 | 充值金额 `0.01..100000.00`；冻结或关闭钱包禁止操作 | 充值幂等且流水与余额一致 |
| 支付 | 创建支付尝试并确认支付 | 只支持钱包；一次父交易最多一次成功；余额不足不扣款 | 支付成功后所有子订单进入待发货 |
| 订单 | 父交易详情、子订单列表/详情、取消待支付交易、确认收货 | 付款前取消整个父交易；发货后按子订单确认 | 快照不随商品/地址修改而变化 |

| 模块 | 功能点 | 关键规则 | 验收结果 |
| --- | --- | --- | --- |
| 工作上下文 | 查看本人店铺和店铺角色 | 只能进入有效成员对应店铺 | 切换店铺后所有请求使用路径 `shopId` |
| 商品列表 | 按状态、名称、编号查询本店 SPU | 只查本店，默认含所有未删除商品 | 展示状态、内容版本、SKU 数、库存汇总 |
| 商品编辑 | 创建 SPU、属性值、SKU；修改受审核内容 | 类目必须为启用叶子；必填属性齐全；规格组合唯一 | 创建后为 `DRAFT` 并产生历史 |

| 商品审核流 | 提交审核、审核通过后上架、主动下架 | 只有 `DRAFT` 可提交；只有 `OFF_SHELF` 可上架 | 状态动作与历史同步 |

| 订单履约 | 本店订单列表、详情、填写物流发货 | 只处理本店 `PENDING_SHIPMENT`；发货扣锁定库存 | 发货后订单为待收货且物流字段完整 |

### 2.3 平台端

| 模块 | 功能点 | 关键规则 | 验收结果 |
| --- | --- | --- | --- |
| 店铺 | 店铺列表、创建、编辑、状态变更 | 由平台直接创建；创建时指定首位 `SHOP_ADMIN`；关闭前无未完结订单/售后 | 店铺和首位成员同事务创建 |
| 类目 | 类目树、新增、编辑、启停 | 不能成环；稳定编码不可修改；有属性或商品引用的叶子不能再变父类目 | 商家只能选择启用叶子类目 |

| 品牌 | 品牌列表、新增、编辑、启停 | 编码唯一且创建后不可修改；停用后不能用于新商品 | 历史商品仍保留品牌引用 |
| 商品审核 | 待审列表、详情、批准、拒绝 | 只处理 `PENDING_REVIEW`；拒绝必须填原因 | 批准进入 `OFF_SHELF`，不自动上架 |

## 4. 关键业务规则

### 4.1 注册和登录

- 用户名长度 `4..64`，只允许字母、数字、下划线，首字符必须为字母。
- 密码长度 `8..72`，必须同时包含字母和数字；后端保存 BCrypt 摘要。
- 注册成功不自动登录，前端跳转登录页，避免注册和登录失败语义混杂。
- 登录失败统一返回 `AUTH_INVALID_CREDENTIALS`，不区分用户名不存在或密码错误。
- `last_login_at` 只在成功登录后更新。

### 4.2 商品公开范围

买家列表和详情必须同时满足：店铺 `ACTIVE`、SPU `ON_SHELF`、SPU 未删除。详情可返回全部未删除 SKU，但只有 `ENABLED` 且库存足够的 SKU 可购买；列表最低价只从有效 SKU 计算。若没有有效 SKU，SPU 不出现在列表。

### 4.3 商品内容变更

名称、类目、品牌、图片、详情、包装、服务说明、描述属性、SKU 规格组合发生变化时：

1. `content_version + 1`。
2. 状态按数据库规则进入 `DRAFT`。
3. 写入 `CONTENT_CHANGED` 历史。

SKU 价格、市场价、条码、启停和库存变化不触发重新审核。新增 SKU、SKU 名称和 SKU 图片变化属于受审核内容；已有 SKU 的规格身份不可修改。受审核内容只允许在 `DRAFT`、`REJECTED`、`OFF_SHELF` 修改；`ON_SHELF` 必须先下架，`PENDING_REVIEW` 必须等待审核结果，`BANNED` 必须由平台先解禁。

### 4.4 购物车失效原因

接口为每条购物车项返回以下 `invalidReason` 之一或 `null`：

`SHOP_UNAVAILABLE`、`PRODUCT_DELETED`、`PRODUCT_OFF_SHELF`、`SKU_DISABLED`、`SKU_DELETED`、`OUT_OF_STOCK`、`QUANTITY_EXCEEDS_STOCK`。

价格变化不是失效原因，返回 `priceChanged=true` 和当前价格；用户在结算页确认最新价格。

### 4.5 下单

- 只能提交当前购物车中已选择且有效的项；也支持请求体显式指定购物车项 ID，但必须属于当前用户。
- 同 SKU 在一次交易中只出现一次。
- 一期运费固定为 `0.00`，买家备注按店铺提交。
- 创建成功后删除已下单购物车项；未选和失效项保留。
- 任一商品校验或库存锁定失败，整个事务回滚，不产生半张交易。
- 下单成功后返回服务端 `payExpireAt`，前端倒计时仅用于显示，以服务端状态为准。

### 4.6 支付和取消竞态

- 支付和取消同时发生时，以先获得父交易锁并成功迁移状态的一方为准。
- 支付看到 `CANCELLED` 返回 `TRADE_NOT_PAYABLE`，不扣款。
- 取消看到 `PAID` 返回 `TRADE_NOT_CANCELLABLE`，不释放库存。
- 支付失败可创建新的支付尝试；同一父交易已有成功支付时直接返回成功结果。

### 4.7 发货与收货

- 一张子订单一次性发货，不支持拆包裹和部分发货。
- 承运商代码、名称和运单号必须同时提交，均去除首尾空白。
- 发货事务将所有 `LOCKED` 明细改为 `DEDUCTED` 并扣除锁定库存。
- 买家只能确认本人 `PENDING_RECEIPT` 子订单；确认后进入 `COMPLETED`。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | 密码摘要、Sa-Token、后端鉴权、店铺范围 SQL、HTML 清洗、敏感错误隐藏 |
| 一致性 | 下单、支付、取消、发货使用本地事务和统一锁顺序 |
| 幂等 | 下单、充值、支付、库存入库必须符合统一 API 契约 |
| 性能 | 普通列表接口在 10 万主表数据、正确索引下 P95 小于 500 ms；动作接口 P95 小于 1 s，不含网络 |
| 分页 | 所有可能增长的列表分页，最大 100 条 |
| 可追踪 | 日志包含 `requestId`、操作者 ID、目标资源 ID、结果码，不记录密码和 Token |
| 可测试 | Service 状态机和金额计算单测；Controller 契约测试；MySQL/Redis 集成测试 |
| 浏览器 | 买家端支持近两版 Chrome/Edge；管理端桌面最小宽度 1280 px |

## 6. 一期验收场景

1. 平台创建店铺、叶子类目、属性模板和品牌，并给店铺分配管理员。
2. 商家创建含两个 SKU 的商品，入库后提交审核；平台批准；商家上架。
3. 两家店铺各有一个上架 SKU，买家将二者加入购物车并一次提交。
4. 数据库产生一张父交易、两张子订单、两条以上明细及对应库存锁定流水。
5. 买家余额不足支付失败且余额不变；充值后重试支付成功且只扣款一次。
6. 两家商家只能看到各自子订单并分别发货；库存锁定量相应扣除。
7. 买家分别确认收货，两张子订单独立完成，父交易保持 `PAID`。
8. 对同一个幂等请求进行三次并发调用，业务结果只发生一次。
9. 使用其他店铺成员访问目标 `shopId` 的商品、库存和订单，均无法获得数据。
10. 修改已下单商品、店铺名和地址后，历史订单快照保持不变。
