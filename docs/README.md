本目录是时光商城当前业务范围的产品、接口、数据库和协作规范入口。系统定位为多商户、类京东的教学商城，当前实现采用 Spring Boot 4、Java 21、MyBatis-Plus、MySQL、Redis 和 Sa-Token。

## 2. 两阶段交付

| 阶段 | 目标 | 主要能力 |
| --- | --- | --- |
| 一期 | 跑通可演示、可验收的多商户交易闭环 | 登录、地址、商品浏览、购物车、跨店下单、库存预占、钱包充值与支付、商家商品/库存/发货、平台店铺/类目/品牌/商品审核 |
| 二期 | 完成当前数据模型覆盖的治理和逆向交易闭环 | 平台 RBAC、店铺成员、商品禁售、库存调整与流水、售后申请/审核/退货/退款、自动取消/完成、重试与对账 |

`database/phase-1-design.md` 文件名沿用最初提交名称，但其 26 表结构是两个产品阶段共同使用的完整数据库基线，不表示二期需要另建一套数据库。

## 3. 文档权威性

当不同材料表述不一致时，按下列规则处理：

1. 数据库最终状态以 [`sql/schema.sql`](../sql/schema.sql) 为基线，并按编号顺序叠加 [`sql/schema2.sql`](../sql/schema2.sql) 等迁移脚本；不得只根据单个脚本判断当前状态。
2. 字段语义、状态迁移、金额公式、事务和锁顺序以 [数据库设计规范](database/phase-1-design.md) 为准。
3. HTTP 路径、请求响应 DTO、鉴权、错误码和幂等规则以 `docs/api/` 为准。
4. 阶段范围、页面能力、业务验收标准以 `docs/product/` 为准。
5. Java 实现必须同时满足上述文档，不得通过实体类反向改变已冻结的外部接口。

如果确实需要修改已冻结规则，必须在同一个变更中同步更新受影响的 SQL、数据库文档、API 文档、产品文档、Java 枚举/DTO 和自动化测试。

## 4. 当前明确不做

当前数据库没有对应模型，下列能力不进入一期或二期：真实第三方支付、商户结算与平台佣金、优惠券/满减/秒杀、评价、收藏、搜索引擎、推荐、站内信、聊天客服、发票、物流轨迹、运费模板、商家资质申请、换货/维修、争议仲裁、文件存储服务、财务提现和多仓库存。

这些能力不得通过在现有字段中塞入非预期 JSON 或复用状态码的方式临时实现；后续立项时应独立补充产品、数据和接口设计。
